# rowuse's allow file: what the check can't decide by its rules (tools/checks/rowuse/Analysis.cs), each with its reason.
#
# The rules (no entry needed): a use of a property's compiler-made backing field (the interop's _Name_k__BackingField) is a
# use of the property's row; the interop's own glue (Il2CppSystem.Object GetIl2CppType and op_Implicit) needs no row; a row
# is used when a string literal of the plugin, Core or the Steam library names its member (a Harmony patch by name, nameof,
# an icall as 'Type::get_Name', the backing field by '<Name>k__BackingField'), when it is a member of an enum the plugin
# names (an enum value is a constant in the code, so no member reference shows it), or when clientmode.txt or
# presentation.txt lists it too (the plugin reads those lists as data at run time; a hand-picked row beside the generated
# list is kept on purpose). A constructor row ('Type::.ctor') is the exception to the string rule: it is used only when the
# built plugin constructs that type (a constructor reference to it), never by a string literal, because one literal ".ctor"
# would name every constructor row at once. A type made some other way (reflection, the game's own CreateInstance or
# AddComponent by a type) has no constructor reference: its row is listed here, saying how it is made. Only hooks.txt and
# menus_initdata.txt rows must be used; clientmode.txt and presentation.txt rows are read as a list by the plugin.
#
# Entries: 'row <Type::Member> | <reason>' keeps a row nothing in the plugin names; 'use <Type::Member> | <reason>' lets the
# plugin use a game member that has no row. An entry that no longer applies fails the check (remove it), so this file only
# shrinks with the code.
