# Presentation: which of the game's event listeners run on a friend's PC (Streaming/EventChannel.cs).
# From a survey of the event buses: every class that subscribes to GameplayEvents, RogueEvents,
# PowerupEvents or ShopEvents was classed presentation, logic, menu or local by its handlers.
# Checked offline by hookcheck.py (every class and event) and, in the game, when a PC first plays a host's stream: a
# [listeners] class missing from the running build is logged as a warning, and the rest of the list still applies.
#
# [listeners]  presentation classes: their listeners get the host's events. Every other listener is detached while
#              client mode is on (so presentation code raising an event locally can't reach game logic) and put back
#              after. A listener's class is its handler's outermost declaring class (SoundManager for SoundManager+<>c).
# [local]      events that presentation code raises itself on a friend's PC: not delivered from the stream, or they'd
#              arrive twice.
# [menu]       events this PC's own pause menu raises, and what playback does: pause, resume, or leave (playback stops
#              and puts the match back first; the game's own exit handlers then get the event). Not leaks.
